## (b) Pre-pilot gaps

- **Account deletion misses 2 user-scoped tables.** Delete loop = `["messages","highlights","goals","snapshots","mutations","assets"]` then `users` then auth user (`src/app/api/users/me/route.ts:123-133`).
  - User-scoped tables found in code: `assets`, `mutations`, `messages`, `snapshots`, `highlights` (`.eq("user_id"…)` `src/app/api/cron/market-highlights/route.ts:100`), `goals`, **`diary_summaries`** (`src/app/api/diary-summary/route.ts:79`), **`vital_snapshots`** (`src/lib/vitals/persist.ts:25`; `docs/vitals-build-state.md:175`), `rate_limits`.
  - **MISSED: `diary_summaries`, `vital_snapshots`** — not in the loop, not the `users` row. Orphaned unless they carry `ON DELETE CASCADE`, which is unverifiable here (no base-schema migration in repo) and is contradicted by the loop's own pattern (it explicitly deletes the other per-user tables rather than relying on cascade).
  - `rate_limits` is safe: explicit `user_id … REFERENCES users(id) ON DELETE CASCADE` (`supabase/migrations/20260508_rate_limits.sql`).
  - `fx_rates` correctly excluded — global, keyed `base,quote` (`src/lib/fx.ts:73`).

- **Insight figures pass through the LLM for phrasing.** Detector numbers are deterministic (`src/lib/portfolio-insights.ts:58,82,123,152-160`) but the displayed sentence is regenerated by Haiku given those numbers (`src/lib/portfolio-insights.ts:165-201`); deterministic `templateSentence` is only the fallback. A model can drift a shown figure. Net-worth/totals/FX are NOT affected (see c).

## (c) Invariant violations

- **"Every portfolio change logs a `mutations` row" — UPHELD for value changes.**
  - add → `src/lib/apply-changes.ts:305`; edit → `:456`; remove → `:495` (insert-before-delete); restore → `src/app/api/assets/route.ts:72`.
  - All asset writes enumerated: `apply-changes.ts:273/443/517`, `api/assets/route.ts:47`, `components/PropertyMap.tsx:188`, `api/backfill/route.ts:91`.
  - Asset writes with **no paired new mutation** (none are value changes, so not violations — flagged for completeness):
    - Pure rename: mutation insert skipped when only `name` changes — by design (`apply-changes.ts:453-454`; `docs/current-features.md:177`).
    - `PropertyMap.tsx:188` — `assets.photo_url` metadata update.
    - `backfill/route.ts:91` — corrects zero `value`/`buy_price`; amends the existing mutation's `after_value` instead (`:87`).

- **"Deterministic math only (totals / net worth / FX)" — NO violation.**
  - Net worth/totals: `computeNetWorth` (`src/lib/utils.ts`), used at `apply-changes.ts:102`, `api/assets/route.ts` (portfolioTotal), `snapshot.ts`. FX: `getUsdRates`/`convertCurrency` from `fx_rates` (`apply-changes.ts:65-71,96`). Tradeable value/units derived from live Yahoo price, not the model (`apply-changes.ts:212-243`). `mutations.portfolio_total` / `snapshots.total_value` computed, not model-emitted.
  - No LLM output feeds a total, net worth, or FX number into storage/display.
  - Note (not a violation of the stated scope): non-priced asset `value` (cash/RE/other) is the user-declared amount transcribed by Claude's extraction and stored directly (`apply-changes.ts:187,273`). It is an input value, not a computed total/NW/FX.

- **Snapshot integrity — UPHELD.**
  - `writeSnapshot` upserts `snapshots {user_id,total_value,breakdown,date}` `onConflict "user_id,date"` → idempotent (`src/lib/snapshot.ts:49-51`).
  - Single shared writer across cron (`api/cron/snapshot/route.ts:20`), per-mutation (`api/chat/route.ts:600`), restore (`api/assets/route.ts:92`).
  - `vital_snapshots` upsert also idempotent: `onConflict "user_id,vital_key,date"` (`src/lib/vitals/persist.ts:31`).
