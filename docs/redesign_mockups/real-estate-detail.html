Page anatomy · why each piece is where it is

The photo hero

Every property has a photo from day one because the photo slot defaults to a dark map of the neighborhood, rendered with the same warm-black + amber palette as the rest of the app. The amber pin marks the property. A "Tap to add photo" hint sits subtle and top-left so users know they can replace it. Tapping anywhere else on the photo opens Google Maps with street view at the property's coordinates.

Address as a clickable link

The address line below the photo is its own click target — full address, city, country, type, size. The small amber arrow icon signals it goes somewhere. This duplicates the photo's click target on purpose: two ways to reach street view, since the photo is also where users will look first.

Equity as the hero, not value

Net worth uses equity, so the property page should too. The big serif number is €237,250 of equity, not €450,000 of gross value. The change pill shows month-over-month equity change, which is the meaningful direction (mortgage paid down + property revaluation combined).

Value composition card

Right below the equity hero, a small card shows the math: value − mortgage = equity as a stacked horizontal bar. Amber for equity, muted grey for mortgage. The bar makes the equity ratio (52.7% in this case) immediately legible. This is the moment that explains why the hero number is what it is.

Mortgage stat grid

Four cards in a 2×2 grid: balance, rate, monthly payment, type. These are the four numbers a homeowner actually carries in their head. Type is set in serif because it's a word, not a number — and because "Annuity" or "Linear" deserves a moment of typographic difference.

Payoff projection chart

A small declining curve from mortgage start to projected end, with a "TODAY" marker showing where the user is on the journey. The curve shape reflects the mortgage type — annuity bows gently at first then accelerates; linear is straight; interest-only is flat (and the "mortgage-free" date would simply read as "—"). Below the chart: paid to date, interest paid, time remaining, mortgage-free date.

Future slots — visible but dim

Two dashed-border cards labelled "Soon": Valuation history (WOZ + market estimate over time) and Cash flow (rent, mortgage outflow, maintenance, net). Showing them at 65% opacity does two jobs: it tells users what's coming, and it commits the page to a layout that won't shift dramatically when those sections arrive. We're not hiding the architecture — we're previewing it.

Activity, scoped to this property

The bottom of the page shows mutations filtered to this asset only — revaluations, extra payments, rate changes. Same journal-feeling treatment as the global Diary, but scoped. Italic context where it exists, monospace numbers where they belong.

Edit and Discuss

Two CTAs at the bottom. Edit opens the manual asset CRUD panel (build-plan item #1). Discuss opens the chat with the property already as context — useful for "what if I pay an extra €200/month?" or "should I refinance at 4.5%?" questions. The chat is already capable of this conversationally; the button is just a shortcut.

Static map · free implementation options

OpenFreeMap + MapLibre

VECTOR · DARK · TRULY FREE

Renders vector tiles in the page using MapLibre GL JS. Hosted by the OpenFreeMap project (community-funded, MIT-licensed). No API key, no signup, no rate limits, no commercial restrictions. Lets us apply a custom dark style that matches the warm-black and amber palette exactly.

  • ~80kb MapLibre bundle, lazy-loaded
  • Custom dark style JSON we ship ourselves
  • Capture as PNG via map.getCanvas().toDataURL() and cache in Supabase Storage
  • Falls back gracefully if offline
openfreemap.org

OSM Static Maps

RASTER · SIMPLE · URL-BASED

A simple HTTP endpoint that returns a PNG given lat/lng/zoom/size. No JS needed — just an <img src="…"> tag. Free, hosted by the OSM community. Limited styling (default OSM look, not dark) but the lowest implementation cost by far.

  • Zero client-side dependencies
  • Default OSM tile style — light, not on-brand
  • Reasonable for prototyping; not for production polish
  • Best as a fallback if MapLibre fails to load
staticmap.openstreetmap.de

Leaflet + CartoDB Dark Matter

RASTER · DARK · FREE FOR SMALL VOLUME

Leaflet renders raster tiles served by CartoDB's free Dark Matter style. Dark by default, decent quality, no key needed. Attribution required. Acceptable for low traffic, but CartoDB asks heavy users to migrate to their paid tier.

  • ~40kb Leaflet bundle
  • Dark theme out of the box, less customizable than vector
  • Tile-based — slightly less crisp than vector at high zoom
  • Migration path if usage grows: switch tile URL to a paid provider
cartodb-basemaps · dark_all
Schema additions · for when we build

New columns on assets for real estate

All optional, nullable, no migration risk on existing rows. Added in a single migration when we start building the page.

addresstext Free-text address. Used for display and as fallback for geocoding when lat/lng aren't set.
latitudenumeric Decimal degrees. Captured automatically by geocoding the address, or set manually. Drives the static map render.
longitudenumeric Decimal degrees. Pairs with latitude.
photo_urltext URL of the user-uploaded photo. When null, the page renders the dark map placeholder instead.
property_typetext "apartment", "house", "townhouse", etc. Free-form for now. Could be enum later if values stabilize.
size_sqmnumeric Floor area in square metres. Used in the address-meta line ("78 m²"). EU standard unit.

Already in schema — no changes needed for these: mortgage_balance, mortgage_rate, monthly_payment, mortgage_type, mortgage_start_date, mortgage_end_date.
